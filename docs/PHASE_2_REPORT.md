# تقرير المرحلة الثانية — تنظيم بنية المشروع

## المنجز
- أضيف توثيق للبنية الحالية وحدود مسؤولية الواجهة وCloudflare Pages Functions.
- أضيف دليل سير عمل GitHub branches وCloudflare Preview Deployments.
- أضيف `package.json` بأمر فحص محلي دون إدخال اعتماديات أو تغيير طريقة تشغيل الموقع.
- أضيف `scripts/check-project.mjs` لفحص مراجع `src` و`href` المحلية في صفحات HTML.
- أبقيت أسماء الملفات والمسارات الحالية كما هي؛ لأن نقلها الآن قد يكسر روابط الصفحات الـ33 والموارد التي تعتمد عليها.
- أبقيت مجلد `a3 2/` كما هو بوصفه نسخة مرجعية قديمة غير محسومة الاستخدام.

## نتائج الفحوص
- فحص صياغة سكربت الفحص: ناجح (`node --check`).
- فحص مراجع HTML: اكتشف 134 مرجعاً محلياً لا يمكن حلّه وفق المسارات الحالية. تتضمن النتائج روابط تنقل من صفحات `blogs/` تستخدم مسارات نسبية إلى صفحات الجذر، ومراجع JSON في `projects.html` لا تقابل ملفات موجودة، بالإضافة إلى موارد أخرى. لم تُجرَ تعديلات آلية عليها لأن بعضها قد يكون مساراً قديماً أو رابطاً خارجياً/ديناميكياً، ويلزم حسم المقصود لكل مرجع.
- لم تُجرَ اختبارات متصفح أو نشر Preview أو اختبار تكاملات حية في هذه المرحلة.

## قرارات معمارية
- إبقاء ملفات HTML والسكربتات المشتركة في أماكنها مؤقتاً للحفاظ على الروابط القائمة.
- عدم إدخال D1 أو KV أو R2 قبل تحديد حاجة وظيفية فعلية.
- الأسرار تبقى في Cloudflare Pages Secrets، وليس في ملفات الواجهة أو Git.

## ما يتطلب معالجة لاحقة
1. مراجعة قائمة المراجع المفقودة وإصلاحها بحسب الوجهة الصحيحة، لا بمجرد إخفاء التحذير.
2. تحديد أي نسخ من مجلد `a3 2/` مستخدمة فعلياً قبل أرشفتها أو حذفها.
3. توحيد تحميل التتبع والنماذج بعد توثيق اعتماد كل صفحة.
4. الانتقال إلى مكونات مشتركة فقط بعد اختيار build strategy واختبارها على نسخة Preview.
