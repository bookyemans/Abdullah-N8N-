# تقرير المرحلة الخامسة — إدارة طلبات التواصل والعملاء المحتملين

## المنجز

- إضافة `supabase/migrations/0004_lead_management.sql` لتوسيع جدول `contact_submissions` بحقول الشركة والخدمة والميزانية ومصدر العميل والملاحظات الداخلية وحالة إرسال الإشعار وتواريخ التحديث.
- إضافة `POST /api/contact` كمسار استقبال موحد من نفس النطاق. يتحقق من Origin وContent-Type وحجم الطلب وصحة الحقول، ويدعم حقل Honeypot والتحقق الاختياري عبر Cloudflare Turnstile.
- حفظ طلب التواصل في Supabase أولاً، وربطه بالزائر والجلسة عند توفر مفاتيح التتبع، ثم تسجيل حدث `contact_submit` دون إدخال بيانات الاتصال الشخصية في خصائص التحليلات.
- نقل إرسال إشعار Web3Forms إلى الخادم باستخدام `WEB3FORMS_ACCESS_KEY` الاختياري. عدم إعداد المفتاح لا يمنع حفظ الطلب في Supabase.
- إضافة `GET /api/admin/leads` مع البحث والحالة والفترة الزمنية والترقيم، وعدادات الحالات، وتصدير CSV لمالك الموقع فقط.
- إضافة `GET/PATCH /api/admin/leads/:id` لعرض تفاصيل الطلب وتغيير حالته وإضافة ملاحظة داخلية، مع تسجيل التغييرات في `admin_activity_logs`.
- إضافة صفحة `/admin/leads.html` وربطها بقائمة الإدارة وتنسيقها مع الهوية الحالية.
- تعديل نموذج التواصل في `contact.html` ليرسل إلى API الداخلي بدلاً من استدعاء Web3Forms مباشرة من المتصفح.

## حالات الطلب

`new`, `in_progress`, `replied`, `closed`, `spam`.

## متغيرات Cloudflare المطلوبة

- `SUPABASE_URL`
- `SUPABASE_ANON_KEY`
- `SUPABASE_SERVICE_ROLE_KEY` (Secret)
- `WEB3FORMS_ACCESS_KEY` (Secret اختياري لإشعار البريد)
- `TURNSTILE_SECRET_KEY` (اختياري؛ لا تضبطه قبل إضافة عنصر Turnstile المقابل في الواجهة)

## تفعيل قاعدة البيانات

يجب تطبيق `0004_lead_management.sql` بعد migrations السابقة. لا يتم تشغيل SQL تلقائياً بمجرد نشر ملفات الموقع.

## الحماية والخصوصية

- لا توجد مفاتيح Supabase أو Web3Forms سرية في JavaScript العام.
- واجهات الإدارة تتطلب جلسة Supabase Auth وحساباً نشطاً في `admin_profiles`.
- تصدير CSV محصور بدور `owner` بسبب احتوائه على بيانات اتصال شخصية.
- لا يتم إرسال الاسم أو البريد أو الهاتف إلى `tracking_events.properties`.
- حفظ بيانات الاتصال ضروري لتنفيذ طلب المستخدم، ويجب تحديد سياسة احتفاظ مناسبة وإظهار إشعار خصوصية واضح في نموذج التواصل.
- الـHoneypot يقلل بعض الرسائل الآلية لكنه ليس بديلاً عن WAF/Rate Limiting أو Turnstile. يوصى بتفعيل Cloudflare Rate Limiting على `/api/contact`.

## حدود التحقق

الاختبارات المحلية تستخدم محاكاة لاستجابات Supabase وWeb3Forms. لم يتم تنفيذ اختبار حي على مشروع Supabase أو إرسال بريد حقيقي أو نشر Cloudflare Preview.

## نتائج الفحص المحلي

- `npm test`: ناجح، بما في ذلك اختبارات Telegram والتتبع وواجهات الإدارة والتحليلات وإدارة العملاء المحتملين.
- `npm run check`: ناجح؛ 39 صفحة HTML، صفر مراجع محلية مفقودة، 12 مشروعاً صالحاً، وفحوص المكونات والأداء وإمكانية الوصول ناجحة.
- فحص بناء JavaScript للسكريبتات المضمنة في `admin/leads.html` و`contact.html`: ناجح.

هذه نتائج محلية ومحاكاة API؛ لا تثبت اتصالاً حياً بـSupabase أو تسليم بريد حقيقي أو نشر Cloudflare.
