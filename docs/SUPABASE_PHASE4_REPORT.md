# تقرير المرحلة الرابعة — تحليلات الزوار ورحلة العميل

## الحالة
تم تطوير لوحة التحليلات وصفحة الزوار محلياً على النسخة السابقة `a5_supabase_phase3_admin.zip`. أصبحت التحليلات تعتمد على استعلام تجميعي داخل PostgreSQL بدلاً من تنزيل آلاف أحداث التتبع إلى Cloudflare Function. لم يتم تطبيق الترحيل على مشروع Supabase حي أو نشر المشروع على Cloudflare.

## ما تم تنفيذه

### 1. تجميع التحليلات داخل PostgreSQL
- إضافة `supabase/migrations/0003_analytics_rpc.sql`.
- إنشاء الدالة `public.admin_analytics_summary(p_days)`.
- تقييد المدة من يوم واحد إلى 90 يوماً.
- التحقق داخل الدالة من أن المستخدم مسؤول نشط عبر `public.is_active_admin()`.
- تنفيذ التجميع داخل قاعدة البيانات: الزوار الفريدون، مشاهدات الصفحات، الجلسات، المشاهدات اليومية، الصفحات الأكثر زيارة، المصادر والحملات، أنواع الأحداث، الدول والأجهزة.
- منح تنفيذ الدالة لدور `authenticated` فقط وسحب صلاحية `anon` و`public`.

### 2. تحديث API التحليلات
- `GET /api/admin/analytics?days=30` يستدعي RPC باستخدام Anon Key ورمز جلسة المسؤول.
- لم يعد ينزل ما يصل إلى 10,000 صف من `tracking_events` لحساب المؤشرات.
- التحقق من المسؤول يتم أولاً في Pages Function، ثم تتحقق دالة SQL أيضاً من هوية وصلاحية المسؤول.

### 3. توسيع صفحة التحليلات
- بطاقات الزوار الفريدين، مشاهدات الصفحات، الجلسات، ونقرات واتساب.
- رسم يومي لمشاهدات الصفحات.
- الصفحات الأكثر زيارة.
- مصادر الزيارات والحملات.
- التوزيع الجغرافي.
- توزيع الأجهزة.
- إحصاءات أنواع الأحداث.
- نطاق زمني 7 و30 و90 يوماً وتحديث يدوي.

### 4. صفحة الزوار ورحلة الزائر
- إضافة فلاتر حسب المصدر والفترة الزمنية.
- إضافة إجمالي النتائج و`has_more` للترقيم.
- إضافة زر لفتح تفاصيل الزائر.
- إضافة `GET /api/admin/visitors/:id` لجلب ملخص الزائر، آخر 50 جلسة، وآخر 100 حدث.
- التحقق من UUID وعدم إظهار المفتاح الكامل للزائر.
- عرض الجلسات والأحداث في Timeline.

## خطوات التفعيل المطلوبة
1. افتح Supabase SQL Editor.
2. طبّق `0003_analytics_rpc.sql` بعد `0001_core_schema.sql` و`0002_analytics_views.sql`.
3. تأكد من وجود مسؤول نشط في `admin_profiles` وأن الحساب يستطيع تسجيل الدخول.
4. انشر نسخة المشروع على Cloudflare Pages بعد ضبط `SUPABASE_URL` و`SUPABASE_ANON_KEY` و`SUPABASE_SERVICE_ROLE_KEY` وفق دليل الإعداد السابق.
5. سجّل الدخول وافتح `/admin/analytics.html` و`/admin/visitors.html`.
6. أنشئ زيارات تجريبية ثم تحقق من الأرقام ورحلة الزائر.

## حدود واحتياطات
- لم يتم إنشاء مشروع Supabase أو تطبيق Migration على قاعدة حقيقية.
- لم يتم نشر أي شيء على Cloudflare.
- لم يتم نقل بيانات D1 التاريخية.
- لا تزال دقة المقاييس معتمدة على الأحداث التي يرسلها المتصفح؛ الحواجز الإعلانية/المتصفحات قد تمنع بعضها.
- بيانات البلد والجهاز لا تظهر إلا إذا تم إرسالها وحفظها في `visitor_sessions`.
- لا تعتبر طلبات صور تتبع البريد دليلاً مؤكداً على قراءة الرسالة.
- للبيانات الكبيرة جداً، الخطوة التالية تكون إضافة تجميعات يومية مادية/مجدولة واحتفاظ وأرشفة، مع اختبار حمل على بيانات ممثلة قبل اعتبار الأداء إنتاجياً.
